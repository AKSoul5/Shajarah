## Shajarah 1.0.58: posters come back at once

Speed. Your families, project files and the database are not changed.

- **A family's poster comes back at once.** Every poster now records how it was made, and the editor keeps that recipe for each family, paper and setting, also between sessions. Asked for the poster again, or after a change, it makes it again from the recipe in one step: a 340-person family's poster at A0 in 0.4 s instead of 104 s, the same poster. The full layout still runs behind it and replaces it only if it finds a better one. Turning spouses back on, on an invented family: 1.7 s became 0.3 s.
- **Export waits for a finished poster.** While a poster is still being worked out the export menu says so, instead of exporting the one shown before.
- A change made while a poster is being laid out now starts the next layout at once.

Layout QA: all 448 posters clean and unchanged.

### Verified before this draft was made
- Typecheck, lint, every unit test and the layout QA (448 cases, no new defect).
- Start-up safety tests with the real PostgreSQL 16 on Linux and Windows.
- Upgrades from every earlier release that still has its installer, using a family created by that release and updated through its own updater. The family is identical afterwards.
- Reinstalling the previous release after updating still opens the family.

### Going back
- **The "latest" label on GitHub.** If 1.0.58 is withdrawn, the previous release is marked latest again. That only stops copies that have **not** updated from being offered 1.0.58.
- **Your installation.** You can install the previous release again over 1.0.58, and your families open unchanged. Do not go back to 1.0.51 or older: they bring back the database deletion defect fixed in 1.0.52.
- **Your data.** 1.0.58 changes no data, so nothing needs restoring.
