## Shajarah 1.0.56: names in proportion on very large posters

Poster fix. Your families, project files and the database are not changed.

- **Names no longer shrink to a fraction of their size on very large posters.** On a very large paper (for example 1024A0) a family whose poster could not be made clean at full size or at the smallest legible size was left at that smallest size: with its daughters hidden, one family's canopy names were a twentieth of their usual size while its long trunk filled the page. The sizes in between are now tried, and the largest clean one is used: that poster's names went from 7.7 mm to 150 mm, clean, and it is laid out faster.
- A size check added in 1.0.55 now only ever accepts a clean poster.

Layout QA: all 448 posters clean and unchanged.

### Verified before this draft was made
- Typecheck, lint, every unit test and the layout QA (448 cases, no new defect).
- Start-up safety tests with the real PostgreSQL 16 on Linux and Windows.
- Upgrades from every earlier release that still has its installer, using a family created by that release and updated through its own updater. The family is identical afterwards.
- Reinstalling the previous release after updating still opens the family.

### Going back
- **The "latest" label on GitHub.** If 1.0.56 is withdrawn, the previous release is marked latest again. That only stops copies that have **not** updated from being offered 1.0.56.
- **Your installation.** You can install the previous release again over 1.0.56, and your families open unchanged. Do not go back to 1.0.51 or older: they bring back the database deletion defect fixed in 1.0.52.
- **Your data.** 1.0.56 changes no data, so nothing needs restoring.
