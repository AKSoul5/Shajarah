## Shajarah 1.0.52: protecting your family database at start-up

**An urgent safety update. Please install it.**

Every earlier version of the desktop app deleted its whole database folder at start-up if one small file in it (`PG_VERSION`) was missing, for example after a partial copy or restore. The families in that folder were lost, although they could have been recovered.

1.0.52 never deletes, overwrites, moves or renames an existing database folder or its password file.

- **A damaged database folder** opens a recovery window, in Arabic and English, that explains the problem. From it you can:
  - make a **repaired copy**, checked and counted before you choose to use it, with the original left untouched;
  - **save your families as project files**, without the app server;
  - **copy the database folder** somewhere safe, with the copy verified file by file;
  - **save a diagnostic report**.
- **A folder whose first set-up was interrupted** (which earlier versions could never start) is kept, and you can start a new, empty database in a new folder.
- **A new install** keeps its database in a folder of its own, recorded in `active.json`.

Nothing else changes. The database schema, project files and posters are exactly as in 1.0.51. Existing installs keep using their current database folder.

### Verified before this draft was made
- Typecheck, lint, every unit test and the layout QA.
- Start-up safety tests with the real PostgreSQL 16 on Linux and Windows. These include the 1.0.51 defect itself, reproduced from the code that shipped.
- Upgrades from every earlier release that still has its installer, using a family created by that release and updated through that release's own updater. The family is identical afterwards.
- Reinstalling 1.0.51 after updating still opens the family.

### Going back
- **The "latest" label on GitHub.** If 1.0.52 is withdrawn, 1.0.51 is marked latest again. That only stops copies that have **not** updated from being offered 1.0.52; it does not change copies that already updated.
- **Your installation.** Copies that already updated stay on 1.0.52 until a newer, fixed version is published. You can also install 1.0.51 again over 1.0.52, and your families open unchanged. **However, 1.0.51 brings the deletion defect back.** After using a repaired copy, do not go back to 1.0.51 or older.
- **Your data.** 1.0.52 changes no data, so nothing needs restoring.
